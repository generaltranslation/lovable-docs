Lovable possui integrações nativas perfeitas para exportar código e adicionar um backend. Mas também é possível integrar uma API externa se você estiver procurando adicionar essa funcionalidade específica ao seu site.

## O que é uma API?

Uma API é uma forma de aplicações de software se comunicarem e compartilharem dados entre si.
Diferentes APIs oferecem diferentes funcionalidades, como enviar emails ou processar pagamentos.
Você pode ler mais sobre o poder das APIs [neste artigo em nosso blog](https://lovable.dev/blog/2025-01-28-the-power-of-apis).

## Usando Qualquer API com Lovable

Todas as outras APIs chamáveis ainda podem ser integradas, mas frequentemente requerem contexto e instruções adicionais.

Você pode ter:

- **Sistemas internos com APIs customizadas**\
  Estes podem ser serviços que sua equipe construiu (ex: sistemas de inventário, pipelines de análise, ferramentas internas) que expõem endpoints REST ou GraphQL mas não são publicamente documentados ou amplamente conhecidos.
  Você quer que o Lovable extraia dados ou envie dados para esses sistemas para automatizar fluxos de trabalho ou alimentar interfaces de usuário.
- **APIs de terceiros que o Lovable ainda não suporta**\
  Talvez você use um produto SaaS de nicho, um provedor de dados especializado, ou uma integração de parceiro que o Lovable não tem conhecimento integrado.
  Mesmo que não seja oficialmente suportado, você ainda quer que o Lovable se conecte, faça chamadas e trabalhe com os dados.

Em ambos os casos, o desafio é o mesmo: o Lovable não "conhece" a API por padrão. Mas com boa documentação e configuração de autenticação, ele ainda pode usá-la efetivamente.
De qualquer forma, a abordagem é a mesma: **o Lovable ainda pode se conectar a ela**. Veja como.

<Steps>
  <Step title="Dê ao Lovable o contexto que ele precisa">
    O Lovable funciona melhor quando entende a API. Você pode fornecer:

    - **Especificação OpenAPI** (se disponível)
    - **Documentação copiada e colada ou exemplos** (especialmente endpoints e exemplos de requisições/respostas)

    Quanto mais clara a documentação, melhor o Lovable pode raciocinar sobre como chamar a API.
  </Step>
  <Step title="Gerencie a autenticação com segurança">
    Para APIs que requerem autenticação:

    **Opção 1: Use Supabase Edge Functions como proxy**

    - Armazene segredos com segurança no Supabase
    - Deixe o Lovable chamar o endpoint da API via Edge Function (não a API diretamente)

    **Opção 2: Implemente a integração da API diretamente no seu projeto Lovable**

    - Exponha um endpoint de autenticação (ex: para trocar credenciais por um token ou sessão)
    - Deixe o Lovable chamar esse endpoint de autenticação como parte do fluxo de integração
    - Inclua tokens, cabeçalhos ou informações de sessão em chamadas subsequentes da API
  </Step>
</Steps>
